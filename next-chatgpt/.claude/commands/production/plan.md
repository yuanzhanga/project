# Phase 2：方案确认 (Plan)

**目标**：基于 Phase 1 的需求摘要，做技术匹配 + 内容方案 + 物料方案，产出结构化确认清单。
**原则**：AI 内部判断技术路线，向用户呈现自然语言推荐。所有方案项必须用户确认后才能进入 Phase 3。
**门禁**：三步全部确认后进入 Phase 3。

---

## Step 2a：玩法匹配

### AI 内部判断（不要向用户暴露技术术语）

1. 读取 `production.md` 中的模板速查表
2. 读取匹配度高的模板的 `CONTENT_SPEC.md` 和 `README.md`
3. 判断：
   - **匹配已有模板** → 只需创建 instance（内容 + 物料），工作量小
   - **无匹配** → 需要新建 template（引擎 + 组件 + 至少 1 个 instance），工作量大
4. 如果是不确定的情况（有模板能部分匹配但需要改造），列出两个选项让用户选择

### 向用户呈现（自然语言）

**情况 A：匹配到已有模板**

> 你的需求可以用 **[模板描述]** 来实现。这个模板支持：
> - <核心玩法点 1>
> - <核心玩法点 2>
> - <核心玩法点 3>
>
> 我们创建一个新 IP **[XX]**，只需要提供故事内容和物料。
> 你觉得这个方向可以吗？

**情况 B：需要新建模板**

> 你的需求比较特殊，现有的模板无法直接覆盖。需要新建一个模板，包括：
> - 设计核心玩法循环和状态系统
> - 搭建游戏引擎和 UI 组件
> - 至少实现一个示范实例
>
> 工作量会比直接用模板大一些，但可以完全匹配你的需求。
> 要继续吗？

**情况 C：有模板可以部分匹配**

> 最接近的是 **[模板 A]**，它支持 <功能 A>、<功能 B>，但缺少你需要的 <功能 C>。
>
> 选项：
> 1. 基于 **[模板 A]** 改造（在现有基础上增加 <功能 C>）
> 2. 从头新建模板（完全定制，工作量更大）
>
> 你倾向哪个？

### 用户确认后进入 Step 2b

## Step 2b：内容方案

### 如果匹配了已有模板（创建 instance）

分析新 IP 和参考模板的差异：

```
保留：核心循环结构、状态数量、UI 布局
修改：角色名/地名/状态显示名、具体文案、图片路径
新增：（尽量少，新增意味着可能需要扩展引擎或组件）
```

确认以下内容：

| 确认项 | 说明 |
|--------|------|
| **IP 名称** | 英文 slug（小写字母 + 下划线，如 `horror_escape`） |
| **规范语言** | 故事原文用什么语言写？（zh-CN 或 en） |
| **章节结构** | 几章？每章的核心事件？ |
| **角色列表** | 每个角色的姓名、性格、在故事中的作用 |
| **结局设计** | 几种结局？各自的触发条件？ |
| **风险点** | 模板是否能覆盖所有需求？哪里有坑？ |

### 如果需要新建模板

确认以下内容：

```
Core Loop：玩家每一轮做什么？（从开始→操作→反馈→推进的完整流程）
状态系统：追踪哪些状态？字段名、含义、高/低走向
UI 布局：几个页面？每个页面的大致布局？
技术栈：React + Vite + ?（需要 AI/视频/音频能力？）
预期工作量：大致多少个 task？
```

### 用户确认后进入 Step 2c

## Step 2c：物料方案

### 物料清单

按模板的 `CONTENT_SPEC.md` 物料规格，列出所有需要的物料：

| 物料 | 数量 | 规格 | 对应环节 | 风格关键词 | 生成渠道 |
|------|------|------|---------|-----------|---------|
| 封面图 | 1 | 1080×1920 jpg | 游戏入口 | <根据 IP 基调> | ai_server |
| 场景背景 | <N> | 1080×1920 jpg | <环节> | <氛围> | ai_server |
| 结局图 | <N> | 1080×1920 jpg | 结局展示 | <情绪> | ai_server |
| 角色头像 | <N> | 200×200 png | 对话/状态 | <性格> | ai_server |
| BGM | 1+ | mp3 | 全程氛围 | <基调> | ArtClaw |

**每个物料的 `image_prompt` 必须在 Step 2c 就写好**（存入内容文件的对应字段），不能等到 Phase 3 编码时再想。prompt 规范见 `production.md` § 物料生成策略。

### Tags 选择

从 `workspace/pub_res/tags.json` 中选择标签：

- **scenario（题材）**：至少选 1 个，最多 3 个
- **background（世界观）**：选 1 个最匹配的
- **audience（受众）**：选 1 个

确认后写入设计文档，Phase 5（ship）阶段用于 publish 配置。

### 用户确认所有物料方案后 → Phase 2 门禁通过

## 门禁确认清单

将以下清单展示给用户，逐项确认：

```
□ 模板选择：[模板名] — 确认玩法匹配？
□ IP 名称：[slug] — 用这个英文名？
□ 规范语言：[zh-CN / en]
□ 内容结构：[N 章] — 每章核心事件确认？
□ 角色：[N 个角色] — 姓名和设定确认？
□ 结局：[N 种结局] — 触发条件确认？
□ 物料：[N 张图 + BGM] — 数量和风格确认？
□ Tags：[tag1, tag2, tag3] — 分类标签确认？
□ 风险点：[可能的坑] — 已知风险了解？
```

全部确认后 → AI 提示：方案确认完毕！进入实现阶段 → `/production:build <change-name>`
