# Phase 1：聊聊想法 (Brief)

**目标**：通过纯对话了解用户想做什么，产出需求摘要。
**原则**：不谈技术。不提模板、目录、框架、生成渠道。用户不需要知道这些。
**门禁**：用户确认需求摘要后进入 Phase 2。

---

## 步骤

### Step 1：了解用户想法

用户可能说得很模糊（"我想做一个恐怖游戏"）或很具体（"我想做一个密室逃脱，有3个房间，每个房间需要找5个线索"）。无论哪种，AI 都从开放问题开始：

- 什么题材/风格？（恐怖、恋爱、悬疑、科幻、奇幻...）
- 核心玩法是什么？（解谜、对话、选择、卡牌、经营...）
- 玩家怎么交互？（点选、输入文字、拖拽、滑动...）
- 怎么算赢/怎么算结束？
- 大概想有多少内容？（几章？几个角色？几种结局？）

### Step 2：深入挖掘

根据用户的初步描述，深入挖掘模糊或缺失的方面：

| 方面 | 可能要问的问题 |
|------|-------------|
| **世界观/背景** | 故事发生在什么时候？什么地点？ |
| **角色** | 有几个重要角色？他们的性格/作用？玩家扮演谁？ |
| **节奏** | 是快节奏紧张感，还是慢节奏沉浸感？ |
| **结局** | 有多少种可能的结局？由什么决定？ |
| **长度** | 玩家玩完一遍大概多久？ |
| **参考** | 有没有类似的游戏或作品可以参考风格？ |

不要一次问所有问题。每次 1-2 个，根据用户的回答自然推进。

### Step 3：产出需求摘要

对话充分后，用以下格式总结：

```markdown
## 需求摘要：<暂定名称>

### 题材与风格
<题材、世界观、氛围、参考作品>

### 核心玩法
<玩家每一轮做什么，从开始到结束的体验>

### 角色
<主要角色列表，每个 1-2 句描述>

### 结局
<几种结局、触发条件概述>

### 内容规模
<章节数、场景数、角色数等估计>
```

### Step 4：门禁确认

将需求摘要展示给用户：
> 这是我根据我们聊的内容整理的。确认无误的话，我进入下一步帮你做具体方案。

- 用户确认 → 进入 Phase 2 (`/production:plan`)
- 用户要求修改 → 回到对应方面，针对性补充或修改
